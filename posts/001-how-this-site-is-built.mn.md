Ихэнх портфолио сайтууд хэзээ ч өөрчлөгддөггүй текстийг харуулахын тулд бүхэл
бүтэн JavaScript framework ачаалдаг. Хурдан нээгдэж, өөрийгөө танилцуулах
гэсэн ганцхан үүрэгтэй хуудсанд энэ нь буруу сонголт мэт санагдсан. Тиймээс
энэ сайт build хийх үедээ бэлдэгдэж, энгийн HTML хэлбэрээр хүргэгддэг.

## Бүх бүтэц

Гурван хэсэгтэй:

1. `content.js` — сайтын бүх текст, нэг объект дотор
2. `posts/*.md` — нийтлэлүүд, frontmatter-тэй markdown хэлбэрээр
3. `build.js` — хоёуланг нь уншаад статик HTML бичнэ

Bundler ч алга, framework ч алга, `node_modules` ч алга. `npm install` юу ч
хийхгүй, учир нь суулгах юм байхгүй. CI checkout-оос deploy хүртэл ойролцоогоор
хорин секунд.

## Энэ юу өгөх вэ

Lighthouse-ийн оноог үнэхээр хөдөлгөдөг шийдвэрүүд:

| Шийдвэр | Үр дүн |
|---|---|
| CSS-ийг `<head>` дотор шингээх | Рендерийг хаадаг stylesheet хүсэлт байхгүй |
| Системийн фонт ашиглах | Фонт татахгүй, солигдох үед layout үсрэхгүй |
| Ганц скриптэд `defer` тавих | Parsing нь JavaScript-ийг хүлээхгүй |
| Статик HTML | Хамгийн том элемент эхний хариунд шууд ирнэ |

Сүүлчийнхийг хүмүүс дутуу үнэлдэг. Хэрэв гарчиг чинь JavaScript-ээр
зурагддаг бол bundle татагдаж, задлагдаж, ажиллаж дуустал LCP болж чадахгүй.
Харин HTML дотор байвал LCP зөвхөн сүлжээний нэг эргэлтээр хязгаарлагдана.

## Чимэглэл биш, аажим сайжруулалт

Интерактив хэсэг бүр аюулгүй доройтдог:

- **Өнгөний сонголт** нь эхний зураглалаас өмнө жижиг inline скриптээр
  `localStorage`-оос уншигддаг тул буруу өнгө анивчихгүй. Хэрэв хадгалалт
  хаагдсан бол системийн тохиргоо руу шилжинэ.
- **Гарчгийн эргэлддэг үг** нь эхний үгээ аль хэдийн агуулсан байдлаар
  сервер дээр бэлдэгддэг. JavaScript зөвхөн хөдөлгөөнийг нэмдэг бөгөөд
  `prefers-reduced-motion` тохиргоотой үед огт ажиллахгүй.
- **Гүйлгэх үеийн илрэл** нь JavaScript ажиллаж байгаа нь батлагдсан үед л
  элементүүдийг нуудаг. Байхгүй бол юу ч нуугдахгүй.
- **Холбоо барих маягт** нь жинхэнэ `action`-тэй жинхэнэ `<form>`. `fetch` нь
  зөвхөн илүү тухтай болгодог; JavaScript-ийг унтраавал энгийн байдлаар
  илгээгдэнэ.

> Миний хэрэглэдэг шалгуур: JavaScript-ийг унтраагаад хуудсыг дахин ачаал.
> Хуудас бүрэн, уншигдахуйц хэвээр байна уу? Хэрэв ямар нэг зүйл алга болвол
> тэр нь бүтэц мэт дүр эсгэсэн чимэглэл байсан хэрэг.

## Ганц овсгоотой хэсэг

Нийгмийн сүлжээнд харагдах зургийг Node-ийн `zlib`-ээр PNG-ийн хэсгүүдийг
шууд бичиж үүсгэдэг:

```js
return Buffer.concat([
  Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]),
  chunk("IHDR", ihdr),
  chunk("IDAT", zlib.deflateSync(raw, { level: 9 })),
  chunk("IEND", Buffer.alloc(0)),
]);
```

Энэ нь нэрийг 5x7 хэмжээтэй bitmap фонтоор градиент дээр зурдаг. Ганц зургийн
төлөө хэтэрхий их ажил мэт — гэхдээ өөр хувилбар нь огт хамааралгүй төсөлд
Puppeteer нэмэх байсныг бодвол зөв сонголт.

---

Framework муу гэсэн үг биш. Харин энэ хуудас ямар ч төлөвгүй, гүн интерактив
байдал шаарддаггүй, ганцхан үүрэгтэй: хурдан байж, үнэн зүйл хэлэх. Тэр үүрэгт
тохирсон хэрэгслийг сонгох нь build систем тохируулахаас бага код шаардсан.
