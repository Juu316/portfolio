Most portfolio sites ship a JavaScript framework to render text that never
changes. That felt like the wrong trade for a page whose entire job is to
load instantly and say who I am, so this one is generated at build time and
served as plain HTML.

## The whole build

There are three moving parts:

1. `content.js` — every piece of copy on the site, in one object
2. `posts/*.md` — writing, as markdown with frontmatter
3. `build.js` — reads both, writes static HTML

No bundler, no framework, and no `node_modules`. `npm install` does nothing
because there is nothing to install. CI goes from checkout to deployed in
about twenty seconds.

## What that buys you

The numbers that actually move a Lighthouse score:

| Decision | Effect |
|---|---|
| CSS inlined into `<head>` | No render-blocking stylesheet request |
| System font stack | No font download, no layout shift on swap |
| `defer` on the only script | Parsing never blocks on JavaScript |
| Static HTML | Largest Contentful Paint is the first response |

The last one is the one people underrate. If your hero text is rendered by
JavaScript, your LCP cannot happen until the bundle downloads, parses, and
executes. If it is in the HTML, LCP is bounded by your network round trip
and nothing else.

## Progressive enhancement, not decoration

Every interactive piece degrades cleanly:

- The **theme toggle** reads `localStorage` in a tiny inline script before
  first paint, so there is no flash of the wrong colours. If storage is
  blocked, it falls back to the OS preference.
- The **rotating hero text** is server-rendered with its first word already
  in place. JavaScript only animates it, and skips entirely under
  `prefers-reduced-motion`.
- The **scroll reveal** only hides elements once JavaScript has confirmed it
  is running. Without it, nothing is hidden.
- The **contact form** is a real `<form>` with a real `action`. `fetch` makes
  it feel nicer; turning JavaScript off just makes it submit normally.

> The test I use: disable JavaScript, reload, and check that the page is
> still complete and readable. If something disappears, it was decoration
> pretending to be structure.

## The one piece of cleverness

The social preview image is generated by writing PNG chunks directly with
Node's `zlib`:

```js
return Buffer.concat([
  Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]),
  chunk("IHDR", ihdr),
  chunk("IDAT", zlib.deflateSync(raw, { level: 9 })),
  chunk("IEND", Buffer.alloc(0)),
]);
```

It renders the name in a 5x7 bitmap font over a gradient. That is absurd for
one image — until you price the alternative, which is adding Puppeteer to a
project that otherwise has no dependencies at all.

---

The point is not that frameworks are bad. It is that this particular page
has no state, no interactivity worth the name, and one job: be fast and say
something true. Matching the tool to that job took less code than
configuring a build system would have.
