## Context

Degfim Dental Group is a Finnish-Mongolian dental clinic in Ulaanbaatar. Its website is one page:
a hero with the phone number, opening hours and address, the services the clinic offers, a short
section about the clinic, and contact details with a map.
{/* src: degfim app/pages/index.vue, app/components/*.vue, README.md */}

## What I did

I built the site alone, as freelance work, in Nuxt 4. Every page is rendered to static HTML at build
time and served by Cloudflare Workers.

<Decision
  locale="en"
  title="One file for the clinic's details"
  problem="Phone, address, hours, social links and services appear in several sections, and in the search metadata too. Copies drift apart when the clinic changes one of them."
  tradeoff="There is no CMS. A change means editing one file and redeploying."
>
  All of the clinic's details live in one data file. The header, hero, services, contact section and
  footer all read from it, so a new phone number or a new service is one edit.
  {/* src: degfim app/data/clinic.ts */}
</Decision>

<Decision
  locale="en"
  title="Prerendered, with structured data from the same source"
  problem="A clinic's site has to be found and has to load fast on a phone, but it does not change between visits."
  tradeoff="Every content change is a rebuild and a redeploy."
>
  Nuxt prerenders the page and Cloudflare Workers serves it as a static asset. The page also carries
  `Dentist` structured data — address, coordinates, opening hours — built from the same data file,
  so what search engines read matches what visitors see.
  {/* src: degfim nuxt.config.ts (nitro preset cloudflare_module, prerender), wrangler.jsonc, app/pages/index.vue */}
</Decision>
